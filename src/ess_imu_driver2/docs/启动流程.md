# IMU 系统启动流程 (单进程热插拔驱动)

> 服务器: 192.168.11.66 (Bianbu 4.0.1, riscv64, ROS2 Humble)
> 硬件: Epson G354PDH0 IMU 载板 (CH343 USB → /dev/ttyACM0~3 或 /dev/ttyUSB*)
> 架构: **单节点 `imu_hub`** — 一个进程管理所有 IMU, 实时热插拔, 实时话题删减

---

## 0. 新架构说明 (2026-08 重构后)

| 项目 | 说明 |
|------|------|
| 启动方式 | 只启动 **1 个节点** (`ros2 launch ess_imu_driver2 imu_hub_launch.py`) |
| 热插拔 | 插入 IMU → 自动识别并发布话题; 拔出 → 话题**实时删除** |
| IMU 数量 | **无上限** (绑定 4 块, 插入第 5 块自动叫 imu5) |
| 绑定 ID | `config/imu_bindings.yaml` 按 **CH343 USB 序列号** 绑定名称 |
| 输出 | **只输出 raw 原始数据** (陀螺仪/加速度/温度), **不含任何滤波/姿态算法** |
| 话题 | `/<名称>/data_raw` (sensor_msgs/Imu), `/<名称>/tempc` (sensor_msgs/Temperature) |
| 滤波算法 | Mahony / EKF 等已全部删除, 只保留驱动 |

## 0.5 硬件绑定 (YAML 配置)

**YAML 绑定文件**: `src/ess_imu_driver2/config/imu_bindings.yaml` (launch 自动加载)

```yaml
imu_bindings:
  A1: "5C38170227"
  A2: "5C38170221"
  B1: "5C38170222"
  B2: "5C38170220"
```

- 驱动通过 sysfs 读取每个设备的 **CH343 USB 序列号**, 命中 YAML 即用对应名称
- **多出的设备** (YAML 未绑定): 命名 `imu(x+1)`, x = YAML 绑定数量 (如 4 个绑定 -> 第 5 个叫 imu5)
- 修改绑定只需编辑 YAML, 重启 launch 生效, 无需改代码/重编译

udev 规则 (`/etc/udev/rules.d/99-imu.rules`) 仍保留, 仅用于生成 `/dev/imu_XXX` 便捷链接 (非命名依据):

```bash
sudo cp ~/imu-udev.rules /etc/udev/rules.d/99-imu.rules
sudo udevadm control --reload-rules
sudo udevadm trigger --subsystem-match=tty
```

验证: `ls -l /dev/imu_*` 应看到 4 个链接; `ls /sys/class/tty/ttyACM*/device/../serial` 查看序列号。

## 4. 启动驱动 (核心步骤, 只此一步)

```bash
ros2 launch ess_imu_driver2 imu_hub_launch.py
# (名称绑定自动从 config/imu_bindings.yaml 读取)
```

启动后终端会持续打印 (约每 1 秒扫描一次):

```
[imu_hub] 检测到 /dev/ttyACM0 (serial 5C38170227) -> 发布 /A1/data_raw
[imu_hub] 检测到 /dev/ttyACM1 (serial 5C38170221) -> 发布 /A2/data_raw
...
[imu_hub] 当前 4 个 IMU 在线 | 话题: /A1/data_raw /A2/data_raw /B1/data_raw /B2/data_raw
```

> 这个终端保持运行, 不要关闭。**插拔 IMU 会自动增删对应话题, 无需重启。**

### ✅ 默认配置

| 项目 | 默认值 | 说明 |
|------|--------|------|
| 输出话题 | `/<name>/data_raw` + `/<name>/tempc` | 只有 raw 数据, 无姿态话题 |
| 数据频率 | **200 Hz** | `imu_dout_rate:=9` (4=125Hz, 8=400Hz) |
| 内部滤波 | TAP32 (32 阶 FIR) | `imu_filter_sel:=5`, 这是 IMU **芯片内部**硬件滤波, 非软件算法 |
| 波特率 | 460800 | `baud_rate:=460800` |
| 扫描周期 | 1 s | `poll_interval:=1.0` |

### 常用变体

| 需求 | 命令 |
|------|------|
| 只识别指定 VID 的 USB 设备 | `ros2 launch ess_imu_driver2 imu_hub_launch.py filter_vid:=1a86` |
| 调整数据频率 (400Hz) | `imu_dout_rate:=8` |
| 关闭温度话题 | `publish_temperature:=false` |
| 自定义扫描路径 | `device_glob:='/dev/imu_* /dev/ttyUSB*'` |

## 5. 验证数据 (新开一个终端)

```bash
source /opt/ros/humble/setup.bash

# 查看话题 (每个 IMU 有 data_raw + tempc 两个话题)
ros2 topic list

# 查看数据频率 (应为 200Hz)
ros2 topic hz /A1/data_raw

# 查看原始数据 (四元数部分无输出, orientation_covariance[0] = -1 表示无姿态)
ros2 topic echo /A1/data_raw --once
```

### 话题与节点对照表

| 名称 | 设备 | 节点 | 数据话题 | 温度话题 | frame_id |
|------|------|------|---------|---------|----------|
| A1 | /dev/imu_A1 | imu_hub | /A1/data_raw | /A1/tempc | A1_link |
| A2 | /dev/imu_A2 | imu_hub | /A2/data_raw | /A2/tempc | A2_link |
| B1 | /dev/imu_B1 | imu_hub | /B1/data_raw | /B1/tempc | B1_link |
| B2 | /dev/imu_B2 | imu_hub | /B2/data_raw | /B2/tempc | B2_link |
| (第5个+) | /dev/ttyACM4 | imu_hub | /imu5/data_raw | /imu5/tempc | imu5_link |

> `/A1/data_raw` 消息内容: `angular_velocity` (rad/s), `linear_acceleration` (m/s²), `orientation_covariance[0] = -1` 表示**不提供姿态** (raw 驱动不含滤波算法, 姿态计算请自行在上层实现)。

## 9. 常见问题

| 现象 | 处理 |
|------|------|
| `ls /dev/ttyACM*` 没有设备 | 重新插拔 USB; `sudo dmesg | grep -i usb` 看内核日志 |
| 某个 data_raw 话题一直不出 | 拔插对应板子; 看驱动终端日志 (会打印失败原因) |
| 名称分配错乱 | 绑定按 CH343 硬件序列号, 不会乱; 若 `/dev/imu_*` 不存在, 先执行 0.5 节恢复规则 |
| 拔出后话题还在 | 等 1 个扫描周期 (默认 1s) 自动删除 |
| 想接超过 4 块 | 直接插, 自动命名为 imu5, imu6, ... 无上限 |
| 需要更高频率 | `imu_dout_rate:=8` = 400Hz (G354 支持, 芯片滤波 32 阶满足) |
| 需要姿态数据 | raw 驱动不含姿态算法; 上层订阅 data_raw 自行解算 (如外部 EKF/互补滤波) |

## 10. 2026-08 架构变更记录

1. **单进程热插拔驱动**: 原 `imu_auto_detect.py` 守护进程 + 每板独立 ROS 节点架构, 改为**单节点 `imu_hub`** (C++, `src/imu_hub_node.cpp`), 内部线程管理所有 IMU;
2. **删除所有滤波算法**: Mahony (`mahony.cpp/h`, `mahony_embedded.h`, `mahony_ahrs_node.cpp`)、EKF (`attitude_ekf.cpp/h`, `ekf_ahrs_node.cpp`)、旧驱动 (`epson_imu_uart_ros2_node.cpp`, `epson_imu_spi_ros2_node.cpp`) 及全部旧 launch 全部删除;
3. **只输出 raw**: 话题改为 `/<name>/data_raw` + `/<name>/tempc`, `orientation_covariance[0] = -1` 表示无姿态; 芯片内部 FIR 滤波 (`imu_filter_sel`) 保留;
4. **实时话题删减**: 设备拔出 → 驱动自动销毁对应 publisher → 话题立即从 ROS 图中消失;
5. **绑定 ID + 无限数量**: YAML 序列号绑定名称, 未绑定设备自动编号, 数量无上限;
6. **修改的文件**:
   - `src/imu_hub_node.cpp` — 新建, 单进程多 IMU 热插拔驱动
   - `launch/imu_hub_launch.py` — 新建, 唯一 launch 文件
   - `CMakeLists.txt` — 只编译 imu_hub_node, 删除 mahony/ekf 目标
